EdgeReps

GitHub Repository

EdgeReps is a an Edge AI System for exercise detection and repetition counting, completed for Embedded AI (ELEN 6908) in Spring 2026.

Design Motivation/Brainstorming

Initially inspired by my New Year’s resolution to do 100 pushups every morning, this system aimed to demonstrate that accurate, real-time exercise rep counting and form feedback can be delivered entirely on edge devices.

While this could have been implemented with a high resolution camera and pre-trained classification models on a Raspberry Pi, my team introduced a low power Xiao Sense ESP32S3 to explore the possibilities of reducing power consumption while maintaining accuracy/user functionality (and add a little novelty/challenge).

With the memory shortage, it is even more pertinent to find ways to have models on devices without heavily draining battery life.

Initial System Architecture

The initially proposed system consisted of a XIAO ESP32S3 and a Raspberry Pi 5 operating in idle and active modes. The ESP32S3 acts as a low-power front-end, monitoring motion, heart rate, and user input. When activity is detected, it triggers the Pi 5 via USB to begin monitoring exercise.

The Pi 5 captures video from a webcam and runs MoveNet Lightning to extract body key points. These are used to compute joint angles, which tracks exercise phases and form. These outputs are combined with sensor inputs to produce a unified understanding of the user’s activity and motion. A final feedback is then given through audio (spoken feedback) and peripheral outputs (OLED display, LEDs, speaker), driven by the Pi 5 module.

Revised System Architecture

After further brainstorming, we quickly realized that using a push button to select an exercise was trivial; at that point, you might as well just manually turn the Pi 5 on. It added zero novelty or technical depth, and the motion/heart-rate sensing provided little value for actual rep tracking. We wondered how would the system account for previous pushups/squats if it only triggered after the user had already elevated their heart rate and started moving? To create a more seamless user experience, we pivoted to making the ESP32S3 an exercise classifier that wakes the system the moment you get into position. This brought us much closer to our vision and gave us the perfect opportunity to build and deploy our own model via Edge Impulse.

The revised system follows the same two-tier architecture. The ESP32S3 operates as a continuously running low-power sentinel, classifying exercise positions at approximately 1.2 frames per second using an Edge Impulse MobileNetV1 classifier deployed on-device. When a position is detected with sufficient confidence for a sustained number of frames, it sends a serial trigger to the Raspberry Pi 5 wirelessly, which activates the webcam and begins full pose estimation. When no exercise is detected, or a 10-second activity timeout is reached, the Pi returns to an idle state where the USB Webcam is no longer recording.

Design Implementation

ESP32S3 (Exercise Classifier)

The ESP32S3 Sense is a compact development board featuring the Espressif ESP32-S3 dual-core Xtensa LX7 processor running at up to 240MHz, 8MB of PSRAM, 8MB of flash, and an integrated OV2640 camera module. Its built-in PCB antenna supports 2.4GHz WiFI and Bluetooth 5.0. At approximately 300mW during active inference, the ESP32S3 serves as the low-power sentinel in the system architecture. The OV2640 camera captures frames at QVGA resolution (320×240), which are then resized to 96×96 pixels for the Edge Impulse classifier. The board’s PSRAM is critical for buffering raw frame data during inference.

The Edge Impulse classifier uses MobileNet 96×96 0.1 (INT8 quantized), trained on a mixed dataset of internet-sourced fitness images (Roboflow) and real-world images captured in the deployment environment, classified 3 states (Pushup, Squat, and Neither). This was the smallest model that we could put on the the 8MB PSRAM to maintain a consistent accuracy.

LEARNING MOMENT: The initial model trained exclusively on internet-sourced images failed to generalize. Retraining with real-world images in the testing was required.

While testing these models with constraints in camera quality and the size of the classification model, a decision was made to have a 5-frame debounce mechanism that prevents spurious triggers. At a confidence threshold of .85 and with captures at 1.2 FPS, this added latency, but reduced the Squat/Neither misclassification rate significantly. Ensuring transient false positives were better filtered before triggering state transitions.

(We have to hold the position for around 4-5 seconds before the system triggers, but hey, the goal was a workout anyway!)

Raspberry Pi 5 Module (Pose Estimation)

The Raspberry Pi 5 serves as the edge compute node for pose estimation. It runs a Flask-based web server that streams a processed video feed over the local network and executes the MediaPipe pose estimation pipeline when triggered. A Logitech C270 USB webcam provides the video input. A WS2182B LED Strip provides visual form feedback, and a USB audio adapter with speaker provides TTS voice feedback via pyttsx3.

MediaPipe Pose was selected for the Raspberry Pi 5 pipeline over alternative frameworks, including MoveNet and Ultralytics YOLOv8-Pose. MoveNet Lightning lacked sufficient landmark density around the elbow and wrist joints for reliable angle calculation. Ultralytics YOLOv8-Pose offers strong multi-person detection, but its resource requirements was overkill for our single-person real-time application on the Pi 5. MediaPipe Pose was chosen for its 33-landmark output, optimized ARM CPU performance, and built-in person detection stage.

Rep Counting

The rep counting mechanism is built on three-point joint angle calculation using MediaPipe’s normalized landmark coordinates. For pushups, the elbow joint angle is calculated from the shoulder, elbow, and wrist on each side. The system uses thresholds of greater than 160 degrees for the up position and less than 80 degrees for the down position, providing a margin that accommodates natural variation in form.

For squats, the relevant landmarks shift to the hip, knee, and ankle on each side. The same angular thresholds apply. The consistency across exercises simplifies the FSM logic, as the same state transition rules apply regardless of which exercise is active.

Requiring both left and right joint angles to cross the threshold simultaneously reduces false positives from asymmetric movement (so no cheating). The intermediate angle detection for form correction feedback adds practical utility beyond simple rep counting, providing actionable coaching cues (‘go down lower’, ‘go up higher’) during exercise. The feedback is communicated through both TTS audio output and LED color signaling.

Pipeline of Algorithms (Psuedocode)
  • Exercise Detection + Debouncing
MODULE ESP32PositionTriggerInference
    CONSTANT CONFIDENCE_THRESHOLD = 0.85
    CONSTANT CONFIRM_THRESHOLD    = 5
    
    STATE last_label      = "neither"
    STATE confirm_count   = 0
    STATE current_trigger = "neither"
    
    FUNCTION setup():
        Initialize Serial at 115200 baud
        Configure Camera Pins and Frame Buffer (QVGA, JPEG format, PSRAM enabled)
        Initialize Camera Sensor (apply vertical flip/brightness if OV3660)
        Warm up Edge Impulse classification runtime
    FUNCTION loop():
        Allocate RGB raw frame snapshot buffer in memory
        
        // Image Acquisition & Preprocessing
        frame = CaptureCameraFrame()
        Convert JPEG buffer to RGB888
        Crop and interpolate to Classifier Dimensions (EI_CLASSIFIER_INPUT_WIDTH x EI_CLASSIFIER_INPUT_HEIGHT)
        
        // Edge Inference
        RunClassifier(signal, result)
        Record and update running averages for DSP Latency and Classification Latency
        
        // Periodic Telemetry (Every 5 seconds)
        IF CurrentTime - LastReportTime >= 5000ms:
            Calculate FPS = frame_count / 5.0
            Print FPS, Latency Metrics, Free Heap, and Free PSRAM to Serial
            Reset frame counter
        END IF
        // Extract Prediction with Highest Confidence
        max_val = 0.0, max_label = "neither"
        FOR EACH class IN result.classification:
            IF class.value > max_val:
                max_val = class.value
                max_label = class.label
            END IF
        END FOR
        // Debounce & Consistency Verification
        IF max_val >= CONFIDENCE_THRESHOLD AND max_label != "neither":
            IF max_label == last_label:
                confirm_count = confirm_count + 1
            ELSE:
                confirm_count = 1
                last_label = max_label
            END IF
            // State Transition Confirmation
            IF confirm_count >= CONFIRM_THRESHOLD:
                IF max_label != current_trigger:
                    current_trigger = max_label
                    IF current_trigger == "squat_position":
                        Serial.Print("TRIGGER:SQUAT")
                    ELSE IF current_trigger == "pushup_position":
                        Serial.Print("TRIGGER:PUSHUP")
                    END IF
                END IF
                confirm_count = 0
            END IF
        ELSE:
            // Signal Loss / Fallback to Neutral
            IF current_trigger != "neither":
                current_trigger = "neither"
                Serial.Print("TRIGGER:NONE")
            END IF
            last_label = "neither"
            confirm_count = 0
        END IF
        Free snapshot buffer
    END FUNCTION
END MODULE
  • Serial -> MQTT Bridge
MODULE SerialToMQTTBridge
    CONSTANT SERIAL_PORT = "COM3"
    CONSTANT BAUD_RATE   = 115200
    CONSTANT MQTT_BROKER = "172.20.10.9"
    CONSTANT MQTT_PORT   = 1883
    CONSTANT MQTT_TOPIC  = "workout/control"
    FUNCTION Main():
        Initialize MQTT Client (Protocol Version 2)
        Connect to MQTT Broker at (MQTT_BROKER:MQTT_PORT)
        Start Background MQTT Network Loop Thread
        Open Serial Connection on SERIAL_PORT with BAUD_RATE (Timeout = 1s)
        WHILE True:
            TRY:
                raw_line = ReadLineFromSerial()
                line = DecodeUTF8AndTrim(raw_line)
                IF line IS EMPTY:
                    CONTINUE
                END IF
                Print "ESP32S3: " + line
                // Trigger Mapping & Dispatch
                IF line == "TRIGGER:PUSHUP":
                    payload = '{"action": "START", "exercise": "PUSHUP"}'
                    MQTTClient.Publish(topic=MQTT_TOPIC, payload=payload)
                ELSE IF line == "TRIGGER:SQUAT":
                    payload = '{"action": "START", "exercise": "SQUAT"}'
                    MQTTClient.Publish(topic=MQTT_TOPIC, payload=payload)
                END IF
            EXCEPT KeyboardInterrupt:
                Close Serial Port
                Stop MQTT Loop & Disconnect Client
                BREAK
            EXCEPT DecodeError:
                CONTINUE
        END WHILE
END MODULE
  • Main Algorithm (MQTT, MediaPipe, LED GPIO)
MODULE EdgeRepDemoPi5
    IMPORT MediaPipePose, OpenCV, Flask, MQTT, Pi5Neo, PSUtil, Subprocess
    GLOBAL is_running = False
    GLOBAL current_exercise = "PUSHUP"
    GLOBAL counter = 0, stage = None, latest_frame = None
    GLOBAL warned_depth = False, warned_height = False
    DEFINE JOINT_MAP:
        "PUSHUP" -> Left/Right (Shoulder, Elbow, Wrist)
        "SQUAT"  -> Left/Right (Hip, Knee, Ankle)
    // Hardware Feedback Helpers
    FUNCTION speak(text):
        Spawn background thread: Execute Shell Command ['espeak-ng', text]
    FUNCTION flash_leds(color_type):
        Spawn background thread:
            IF color_type == "success": Fill Strip Green (0, 255, 0)
            ELSE IF color_type == "error": Fill Strip Red (255, 0, 0)
            Sleep 0.3s
            Clear Strip
    FUNCTION calculate_angle(A, B, C):
        Calculate 2D planar vector angle at joint B using arctan2
        Normalize absolute degree result between [0.0, 180.0]
        RETURN angle
    // Asynchronous Inference Engine
    FUNCTION pose_worker():
        Open Local Camera (/dev/video0)
        Initialize MediaPipe Pose (min_detection=0.5, min_tracking=0.5)
        WHILE is_running AND Camera IS Open:
            frame = ReadCameraFrame()
            landmarks = MediaPipe.Process(RGB(frame))
            IF landmarks ARE Present:
                // Extract Kinematic Joint Coordinates
                joints = JOINT_MAP[current_exercise]
                angle_L = calculate_angle(joints.left.A, joints.left.B, joints.left.C)
                angle_R = calculate_angle(joints.right.A, joints.right.B, joints.right.C)
                // Repetition & Quality Finite State Machine
                IF angle_L > 160 AND angle_R > 160:
                    IF stage == "down":
                        counter = counter + 1
                        speak(ToString(counter))
                        flash_leds("success")
                        last_active_time = CurrentTime()
                    ELSE IF warned_depth:
                        speak("Go down lower")
                        flash_leds("error")
                        warned_depth = False
                    END IF
                    stage = "up"
                    warned_height = False
                ELSE IF angle_L < 80 AND angle_R < 80:
                    IF warned_height:
                        speak("Go up higher")
                        flash_leds("error")
                        warned_height = False
                    END IF
                    stage = "down"
                    warned_depth = False
                // Intermediate Form Check Flags
                ELSE IF angle_L > 100 AND angle_R > 100 AND stage == "down":
                    warned_height = True
                ELSE IF angle_L < 150 AND angle_R < 150 AND stage == "up":
                    warned_depth = True
                END IF
                Overlay joint angles and skeleton on frame
            END IF
            // Timeout Gating
            IF CurrentTime() - last_active_time > 10.0 seconds:
                is_running = False
                speak("Session timeout. You completed X exercises")
            Render Dashboard UI (Reps, Stage, Idle Timer)
            Encode frame to JPEG -> update latest_frame buffer
            Record instantaneous FPS & CPU utilization
        END WHILE
        Release Camera
        Write workout duration, average FPS, CPU, clock, and throttling to "workout_history.log"
    // Network Control Callbacks
    ON MQTT Message Received (payload):
        Parse JSON payload:
        IF action == "START" AND NOT is_running:
            current_exercise = payload.exercise
            counter = 0, stage = None, is_running = True
            speak("Starting " + current_exercise + " mode")
            Spawn pose_worker thread
        ELSE IF action == "STOP":
            is_running = False
            speak("Session stopped.")
    // HTTP Video Streaming
    ROUTE "/video_feed":
        Stream latest_frame as multipart/x-mixed-replace JPEG boundary buffer
    MAIN:
        Initialize SPI Pi5Neo Strip on /dev/spidev0.0 (200 LEDs)
        Start background CPU hardware monitor thread
        Connect MQTT Client to localhost:1883, subscribe to "workout/control"
        Launch Flask HTTP Server on 0.0.0.0:5000
END MODULE

Takeaways

Power Consumption Improvement

As mentioned before, this could have just been completed entirely on the Raspberry Pi with a more robust classification model, but having this two tier system provided an opportunity for reducing power consumption.

Raspberry Pi 5 can operate in two modes:

  • Baseline Mode: MediaPipe runs continuously (benchmark state operating independently of the classifier)
  • Trigger-Gated Mode: MediaPipe executes when a trigger is received from classifier

In 3 minute demos (Alternating between doing exercises and resting) we observed this power consumption profile:

I also added in a part to the script that tracks the average clock speed and the usage during each session, where the Baseline Mode was 2400 MHz (Peak Clock Freq.) and Trigger-Gated was 2100 MHz.

There are a few scenarios that could cause the clock speed to lower:

  • Idle / Low Workload (Normal): The Linux CPU dynamically scales down frequency (down to 1500 MHz on the Pi 5) when demand drops.
  • Thermal Throttling (Overheating): If the Broadcom BCM2712 SoC crosses approximately 80°C to 85°C under sustained load, the hardware throttles clock speeds down to prevent silicon damage.
  • Under-voltage (Power Issues): If the power delivery falls below ~4.8V (e.g. insufficient USB-C supplies or inadequate cable gauge), the PMIC triggers an under-voltage event and downclocks the CPU to protect stability.

Because Idle Mode in Pi 5 is 1500 MHz, this suggests that the state could have been reached for an amount of time to lower the average from 2400 MHz to 2100 MHz. Also, given that the power source was from a wall outlet (no lack of current to throttle clock speed) and the temperature remained below the 80°C threshold, we concluded that the Pi 5 achieved an idle state between workouts.
